# Oguzki · Support Copilot

Кейс 03 Grand Mobile × Decentrathon 6.0 — ассистент поддержки и разбора жалоб.
Команда Oguzki. Версия 0.11.0: персональные сессии, подписанный игровой вход и адаптер организационного OIDC/MFA.
Конфигурация развёртывания: [docs/production-access.md](docs/production-access.md).
Проверки безопасности и их границы: [docs/security-audit.md](docs/security-audit.md).
SSO у провайдера, публичный сертификат, защита main и внешний пентест ещё требуют действий владельца; наличие конфигурации не означает их активацию.
Отчёт о сдаче: [docs/wave-7.md](docs/wave-7.md). Коннектор: [docs/game-connector.md](docs/game-connector.md).
Аудит-цепочка: [docs/audit-chain.md](docs/audit-chain.md).

## Назначение

Сервис принимает обращение игрока (вопрос, проблему или жалобу) и готовит для
оператора разбор:

- язык, категорию и приоритет;
- нужна ли передача человеку и почему;
- извлечённые ник, сервер и ссылки на правила;
- найденные пункты правил;
- черновик ответа на языке игрока: RU, KK, UZ, а также EN/ES/PT.

Решение остаётся за человеком. Сервис не наказывает, не возвращает деньги,
не разбанивает и не утверждает, что просмотрел скриншоты. Черновик собирается
из проверенных формулировок, а не из свободного текста модели.

Значимые действия операторов и системы записываются в подписанную хеш-цепочку.
Попытка подменить прошлое ломает цепочку, и это видно одной проверкой.

## Архитектура

```text
POST /triage ─┐
make predict ─┼─► service.triage ─► analyze: язык, категория, приоритет, извлечение
UI /operator ─┘                     safety: платежи, аккаунты, апелляции, противоречия, подмена инструкций
                                    knowledge: индекс 267 пунктов правил, поиск, разрешение ссылок
                                  ─► drafting: план ответа → проверка цитат и эскалации → локализованный текст
                                     (шаблоны по умолчанию; Responses API — только явно)

действие оператора, разбор, событие игры ─► audit_chain: блок в той же транзакции ─► зеркало и якоря
```

| Модуль | Роль |
|---|---|
| `schemas.py` | Строгий контракт запроса и ответа (Pydantic, лишние поля отклоняются) |
| `service.py` | Единое ядро для HTTP, CLI и интерфейса |
| `safety.py` | Независимая от модели проверка рисков и обязательной эскалации |
| `knowledge.py` | Загрузка и проверка rules/taxonomy, поиск (RAG), составные ID `раздел:пункт` |
| `drafting.py`, `draft_text.py`, `citation_policy.py` | План ответа, проверка цитат, тексты RU/KK/UZ |
| `draft_provider.py`, `deadline.py`, `costing.py` | Опциональная модель: срок ожидания, слоты, учёт usage и стоимости |
| `api.py`, `operator.py`, `operator_store.py`, `static/` | FastAPI, рабочее место оператора, локальная SQLite-история |
| `cli.py` | `make predict`: JSONL на входе и выходе |
| `evaluate*.py`, `measure.py`, `benchmark.py`, `review.py` | Метрики, регрессии, задержка, пакет человеческой оценки |
| `submission_check.py`, `repo_audit.py` | Проверка сдачи и аудит Git (Wave 7) |
| `connector.py`, `mock_provider.py` | Имитация входа из игры, вымышленные профили, исходящие действия через локальный outbox |
| `security.py`, `auth_store.py`, `game_ingestion.py` | Защита всех HTTP-маршрутов, сессии и роли сотрудников, HMAC входящих игровых событий |
| `audit_chain.py`, `chain_signer.py`, `chain_cli.py`, `audit_api.py` | Подписанная хеш-цепочка действий: запись, проверка, якоря, вкладка AUDIT CHAIN (Wave 8) |

Чат с внешней моделью для MVP: [docs/capybara-mvp.md](docs/capybara-mvp.md).

## Запуск

Нужны Python 3.11+, GNU Make и локальные справочники (см. «Данные»).

```bash
make install                      # venv + зависимости из requirements-dev.lock
.venv/bin/python -m support_copilot.manage_operators create --username arnur --role admin
# Пароль задаётся интерактивно владельцем, минимум 15 символов; общего пароля нет.
# Только для loopback HTTP на своей машине:
export COPILOT_INSECURE_LOCAL_HTTP=1
make serve                        # http://127.0.0.1:8000/  ·  Swagger: /docs
make predict IN=examples/wave7_demo.jsonl OUT=outputs/pred.jsonl
COPILOT_DRAFT_PROVIDER=template make check   # полная проверка перед сдачей
```

По умолчанию панель и API требуют вход. Откройте `/auth/login` и войдите
созданной учётной записью. Для HTTPS переменная `COPILOT_INSECURE_LOCAL_HTTP`
не нужна. Сессии: HttpOnly, SameSite=Strict, Secure по умолчанию; запись через
cookie требует Origin. Подробности, роли и установка: [docs/security.md](docs/security.md).

Windows: `./run.ps1 -Install`, затем `./run.ps1` (сервер) или
`./run.ps1 -Mode Test | RegressionEvaluate | DraftEvaluate | SubmissionCheck | AuditRepo | ChainVerify`.

В панели нажмите **«Загрузить тестовый кейс»**: выберите один из пяти сценариев
или введите своё обращение и ID игрока. Разбор выполняется сразу без API модели.
В карточке доступны вымышленный профиль, баланс и до трёх транзакций.
**«Отправить ответ · MOCK»** и **«Передать человеку»** записывают действие в
SQLite, консоль и файл-аудит; результат виден во вкладке **«Доставка · MOCK»**.
Ни игра, ни Telegram, ни ClickHouse фактически не подключены.

```bash
curl -X POST http://127.0.0.1:8000/triage -H 'Content-Type: application/json' \
  -H "Authorization: Bearer $COPILOT_TRIAGE_TOKEN" \
  -d '{"kind":"complaint","messages":[{"role":"player","text":"Меня оскорбили на сервере 4","attachments":1}]}'
```

Для этого машинного вызова задайте серверу и клиенту один случайный
`COPILOT_TRIAGE_TOKEN` (32+ символа). Он разрешает только `/triage` и `/health`;
это не токен оператора. Секрет не передавайте в URL или Git. Из браузера `/triage`
доступен вошедшему оператору. CLI авторизацию HTTP не использует.

`make predict`: одна строка входа — один запрос по контракту, одна строка выхода —
ответ в том же порядке. Ошибка формата указывает номер строки и не портит прежний
OUT. HTTP и CLI вызывают одно ядро и дают одинаковый JSON.

Внешняя модель выключена (`COPILOT_DRAFT_PROVIDER=template`). Для подключения
задайте в окружении `OPENAI_API_KEY`, `COPILOT_MODEL` и `COPILOT_DRAFT_PROVIDER=responses`.
`.env` не читается автоматически. Ключ в Git не добавлять.

## Аудит-цепочка

Каждый блок хранит хеш предыдущего и подпись, поэтому правка любой записи ломает
цепочку от этого места до головы. На одном сервере изменить данные может тот, кто им
управляет. Сделать это незаметно он не может, пока у него нет ключа подписи и пока
существует внешняя копия. Точное название такой схемы — tamper-evidence, а не блокчейн
с консенсусом.

В цепочку попадают разбор, ответ игроку, передача человеку, вход и выход операторов,
действия админа и подписанные события игры. Текста обращений и черновиков там нет; присутствуют хеши и метаданные, включая
идентификаторы. Для содержимого используется SHA-256: можно показать текст и доказать, что он совпадает с блоком #N, не
раскрывая его в журнале. `make predict` и оценки в цепочку не пишут.

В панели откройте **AUDIT CHAIN** и нажмите **«Проверить целостность»**. Как вживую
увидеть обнаружение подделки (используйте отдельную демо-базу, после порчи цепочка
остаётся сломанной):

```bash
export COPILOT_OPERATOR_DB=outputs/demo/workspace.sqlite3
export COPILOT_INSECURE_LOCAL_HTTP=1
make serve
```

Выполните несколько действий в панели, затем во втором терминале с той же
`COPILOT_OPERATOR_DB`:

```bash
COPILOT_CHAIN_TAMPER_DEMO=1 make chain-tamper
```

Повторная проверка покажет красный статус и номер испорченного блока.

| Команда | Действие |
|---|---|
| `make chain-verify` | Полная проверка: блоки, подписи, зеркало, якоря |
| `make chain-export` | Экспорт в `outputs/chain-export.jsonl`; проверяется без базы и закрытого ключа |
| `make chain-anchor WAVE_DOC=docs/wave-8.md` | Подписанный якорь и строка `head_hash`, которую нужно закоммитить |
| `make chain-tamper` | Демо-порча, только при `COPILOT_CHAIN_TAMPER_DEMO=1` |
| `make chain-bench` | Замер записи и проверки на временной базе |

`GET /audit/verify` и `GET /audit/blocks` доступны вошедшему оператору,
`POST /audit/checkpoint` — только админу.

По умолчанию подпись Ed25519: открытый ключ лежит в первом блоке, проверить цепочку
может кто угодно. Если ключ не задан, он создаётся рядом с базой. Для демо этого
достаточно, в развёртывании задайте `COPILOT_CHAIN_PRIVATE_KEY` или
`COPILOT_CHAIN_KEY_FILE` вне тома с данными и закрепите `COPILOT_CHAIN_PUBLIC_KEY`.
Смена ключа, режим HMAC, восстановление из бэкапа и сценарий демо для жюри описаны в
[docs/audit-chain.md](docs/audit-chain.md).

## Данные

Нужны `data/handout-2026-10-27/rules.json` и `taxonomy.json` из разрешённого
архива организаторов. Их SHA-256 зафиксированы в `evaluation/frozen-inputs.json`.
Для метрик (`make measure`) также нужны локальные dev/control-файлы по тем же путям.

В Git нет датасетов, справочников, баз и ключей: `data/`, `outputs/`, `*.sqlite3`,
`.env` игнорируются. `make audit-repo` проверяет всю историю. Примеры в `examples/`
написаны вручную и не взяты из данных Grand Mobile. Подготовка данных Wave 1:
[docs/wave-1.md](docs/wave-1.md).

## Ограничения

- Лексический классификатор: 57% по категориям. Система — помощник оператора,
  не автоответчик; на control все обращения передаются человеку.
- Нет справочника ответов: на игровые вопросы сервис не отвечает сам, а передаёт их сотруднику.
- Живая модель, её стоимость (цель $0.002) и p95 не измерены. $0 — только API модели в шаблонном режиме.
- Человеческая оценка черновиков и носителями KK/UZ не проведена; в control один пример KK.
- Семантической дедупликации обращений нет. Коннектор предотвращает лишь повторы
  одного события/действия по UUID. Вложения не просматриваются, реальной доставки
  в игру нет. Есть персональные сессии и роли операторов; SSO и MFA ещё не подключены.
  Локальный MVP: не выставлять в интернет.
- Чистая установка, полный `make check` и пересчёт control выполнены на Linux
  (Python 3.13.11). macOS и Windows отдельно не проверялись;
  результаты и границы проверки — в [docs/wave-7.md](docs/wave-7.md).
- Аудит-цепочка — подписанная хеш-цепочка на одной ноде, а не консенсус. Компрометация
  сервера вместе с ключом подписи позволяет переписать историю, спасает только внешний
  якорь или зеркало. Правки обнаруживаются всегда, удаление хвоста — при сравнении с
  внешним якорем. Сырого текста обращений в цепочке нет, только дайджесты. Цепочка —
  журнал, а не валидатор: на решения системы она не влияет.
