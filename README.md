# Oguzki · Support Copilot

[Отчёт о качестве и ограничениях](REPORT.md)

Oguzki triages game-support requests and produces grounded drafts for operators.
Use the template provider for offline processing. Put the organizer's rules and
taxonomy into `data/handout-2026-10-27/`, then run the jury API or JSONL CLI.
No game delivery is performed. The measured limits and sample provenance are
described below; the category model is optional and not independently evaluated.

## Быстрый старт API для жюри (Linux/macOS)

Положите разрешённый архив организаторов в текущую папку. Архив содержит
`handout/rules.json` и `handout/taxonomy.json`; команда извлекает только их.
Python 3.13 и зависимости зафиксированы в lock-файле.

```bash
mkdir -p data/handout-2026-10-27
tar -xzf grand-support-copilot-handout-2026-10-27.tgz -C data/handout-2026-10-27 --strip-components=1 handout/rules.json handout/taxonomy.json
make install
export COPILOT_TRIAGE_TOKEN=$(python3 -c "import secrets; print(secrets.token_urlsafe(32))")
make serve-api &
curl -s -X POST http://127.0.0.1:8000/triage -H "Authorization: Bearer $COPILOT_TRIAGE_TOKEN" -H 'Content-Type: application/json' -d '{"kind":"complaint","messages":[{"text":"Меня оскорбили на сервере 4"}]}'
make predict IN=examples/wave7_demo.jsonl OUT=outputs/pred.jsonl
```

`serve-api` запускает только `/triage` и `/health` на loopback; оба требуют
указанный токен. Нехватка токена или справочников останавливает запуск. Отсутствие
`kind` трактуется как жалоба с обязательной проверкой человеком, неизвестное
значение отклоняется; лишние поля игнорируются и не поступают в анализ.
Пакетный `predict` не требует токена и сети в template-режиме. Экран оператора
запускается отдельно через `make serve` и имеет другую настройку авторизации.

Windows PowerShell: поместите два справочника в `data/handout-2026-10-27/`,
затем выполните `./run.ps1 -Mode ServeApi -Install` после установки переменной
`$env:COPILOT_TRIAGE_TOKEN`. В отдельном окне пакетный запуск:
`./run.ps1 -Mode Predict -InputFile examples/wave7_demo.jsonl -OutputFile outputs/pred.jsonl`.

Для экспериментального внешнего режима задайте через окружение
`COPILOT_DRAFT_PROVIDER=responses`, `OPENAI_API_KEY` и `COPILOT_MODEL`. Качество,
затраты и p95 живого провайдера в этой версии не подтверждены; приватные тексты
не отправляйте внешнему провайдеру без отдельного согласования.

Сервис триажа обращений игроков для кейса 03 Grand Mobile × Decentrathon 6.0.
**Версия 0.11.0.** FastAPI, Python, SQLite, веб-панель оператора.
По умолчанию работает локально на шаблонах, без внешней модели и её ключа.

Сервис принимает жалобу из лаунчера (`complaint`) или репорт из игры (`report`),
определяет язык, категорию и приоритет, извлекает факты, находит правила и готовит
черновик. Возвращает `needs_human`, причины решения и эвристическую уверенность.
Это помощник оператора: доказанного качества для массовых автоответов пока нет.

## Что реализовано

- Определение RU/KK/UZ/EN/ES/PT; `und` для неопределённого языка. Локализованные
  черновики для шести языков; наличие перевода не означает подтверждённое качество.
- Лексическая классификация и независимые проверки рисков: платежи, доступ к
  аккаунту, апелляции, противоречия и попытки подмены инструкций.
- Извлечение ника, номера сервера, упоминаний правил и количества заявленных вложений.
  Изображения не читаются; `has_evidence` остаётся `false`.
- Поиск по локальным правилам: BM25, символьные триграммы и объединение рангов;
  исходный поиск доступен для сравнения. В проверенном справочнике — 267 пунктов.
- Черновик из контролируемых формулировок. При подключении модели проверяется её
  структурированный план, ссылки и цитаты; произвольный текст модели не становится
  текстом ответа игроку. Ошибка плана или превышение срока ожидания дают шаблон.
- Панель: поиск и фильтры обращений, карточка с разбором и правилами, редактирование
  черновика, история действий, эскалация и mock-доставка.
- Simhash-поиск повторяющихся длинных сообщений внутри обращения. В панели отдельно
  доступны кандидаты дублей среди последних 500 кейсов. Автоматического слияния нет;
  поле `is_spam_or_duplicate` не является полноценным классификатором спама.
- Feedback loop: правка оператора → очередь → подтверждение другим lead/admin →
  экспорт структурированных меток без текста обращения. Автообучения нет.
- Персональные учётные записи и роли `agent`/`lead`/`admin`, подписанный HMAC-вход
  игровых событий, OIDC-адаптер и подписанный журнал действий.

Сервис не наказывает игроков, не возвращает деньги и не разбанивает аккаунты.
Ссылки на правила проверяются по справочнику; это не доказывает правильность
классификации или смысловую уместность каждого выбранного пункта.

## Архитектура и контракт

```text
POST /triage ─┐
make predict ─┼─► service.triage ─► анализ + safety ─► поиск правил ─► проверенный черновик
UI /         ─┘

Панель / → API /operator/* → SQLite: обращения, решения, feedback, mock-outbox
Игровой HMAC-вход /api/v1/game/* → локальный коннектор
Действия по обращению → подписанный журнал; зеркала и якоря для проверки
```

Запрос к `POST /triage`:

```json
{
  "kind": "complaint",
  "messages": [
    {"role": "player", "text": "Меня оскорбили на сервере 4", "attachments": 1}
  ]
}
```

Схемы запросов и ответов: [schemas.py](support_copilot/schemas.py).
Ответ содержит `lang`, `category`, `priority`, `is_spam_or_duplicate`, `extracted`,
`retrieved_rules`, `reference_resolutions`, `draft_reply`, `needs_human`,
`confidence`, `confidence_level`, `reasons`, `safety_flags` и `generation`.
`confidence` не откалибрована как вероятность правильного ответа.

HTTP, CLI и панель используют одно ядро. Равенство JSON HTTP/CLI проверяется
в шаблонном режиме. HTTP дополнительно пишет аудит; пакетный CLI этого не делает.

## Локальный запуск

Команды ниже выполняются из корня клона. Нужны GNU Make, Git и Python:
в проекте заявлен **Python ≥3.11**, текущий Linux-прогон выполнен на **3.13.11**.
Для повторения проверенного окружения используйте Python 3.13.

Сначала положите разрешённые организаторами справочники в:

```text
data/handout-2026-10-27/rules.json
data/handout-2026-10-27/taxonomy.json
```

Установка и пакетный разбор:

```bash
make install
COPILOT_DRAFT_PROVIDER=template make predict IN=examples/wave7_demo.jsonl OUT=outputs/pred.jsonl
```

Одна строка JSONL — один запрос по приведённому контракту; выход сохраняет порядок.
Сырые строки обучающего датасета имеют другую структуру: их готовит
[адаптер данных](docs/wave-1.md). Ошибка входа указывает строку; выходной файл
заменяется только после успешной обработки всего входа.

Для панели создайте оператора и запустите сервер в отдельном терминале:

```bash
.venv/bin/python -m support_copilot.manage_operators create --username arnur --role admin
export COPILOT_DRAFT_PROVIDER=template
export COPILOT_INSECURE_LOCAL_HTTP=1
make serve
```

Пароль вводится интерактивно, минимум 15 символов; общего пароля нет.
`make serve` занимает терминал и слушает `127.0.0.1:8000`.
Откройте [вход](http://127.0.0.1:8000/auth/login), затем
[панель](http://127.0.0.1:8000/). `/docs` доступен авторизованному оператору.
Разрешение insecure HTTP предназначено только для loopback на своей машине;
для HTTPS эта переменная не нужна. Cookie: HttpOnly, SameSite=Strict,
Secure по умолчанию; записи через cookie требуют проверки Origin.

Для машинного вызова задайте серверу **до запуска** и клиенту один случайный
`COPILOT_TRIAGE_TOKEN` длиной не менее 32 ASCII-символов. Он разрешает только
`/triage` и `/health`, без доступа к панели и `/docs`:

```bash
curl --fail-with-body http://127.0.0.1:8000/triage \
  -H 'Content-Type: application/json' \
  -H "Authorization: Bearer $COPILOT_TRIAGE_TOKEN" \
  -d '{"kind":"report","messages":[{"role":"player","text":"Застрял в текстурах","attachments":0}]}'
```

Подробности авторизации: [docs/security.md](docs/security.md).
Windows-скрипт содержит отдельные режимы, например `./run.ps1 -Install`,
`./run.ps1 -Mode Test` и `./run.ps1 -Mode SubmissionCheck`.
На Windows выполнен smoke-тест в чистом локальном клоне; macOS не проверена.

## Коннектор и демонстрация

Кнопка **«Загрузить тестовый кейс»** позволяет выбрать один из пяти сценариев
или создать своё обращение через `POST /api/v1/simulate-ticket`.
В режиме `template` разбор не вызывает внешнюю модель. Профили, баланс и до трёх
транзакций игрока — локальные вымышленные данные.

**«Отправить ответ · MOCK»** и **«Передать человеку»** сохраняют действие в SQLite;
mock-outbox и журнал показывают имитацию отправки. Реальной доставки в игру,
Telegram или ClickHouse нет. HMAC-эндпоинты для игровых событий реализованы,
но подключение настоящего игрового клиента не подтверждено.
API и сценарий показа: [docs/game-connector.md](docs/game-connector.md).

## Внешняя модель и чат оператора

`COPILOT_DRAFT_PROVIDER=template` — режим по умолчанию. Реализованы явные режимы
`responses` и `capybara`; `.env` автоматически не загружается.
Настройка Capybara через серверный файл ключа:
[docs/capybara-mvp.md](docs/capybara-mvp.md). Ключ не помещается в Git или браузер.
Доступность названия модели у посредника не доказывает её фактического поставщика.

Два разных сценария нельзя смешивать:

- **Черновик игроку:** модель предлагает структурированный план, затем локальная
  проверка и сборка текста. Deadline по умолчанию — 4 секунды; fallback — шаблон.
- **ИИ-помощник оператора:** отдельный свободный совет через Capybara. Проверяются
  JSON-схема и точность приведённых цитат, но не доказанность каждого утверждения.
  Чат не меняет кейс и ничего не отправляет игроку. Последние четыре реплики
  передаются из текущего окна; постоянной серверной истории этого чата нет.

При timeout фактическое списание может оставаться неизвестным. Жёсткая гарантия
**≤ $0.002 за обращение не реализована**. Маскирование распознаваемых секретов,
контактов и идентификаторов перед API не обеспечивает полной анонимности.

и не гарантия отсутствия уязвимостей.

## Аудит и эксплуатационные границы

Журнал — подписанная хеш-цепочка одного узла, без распределённого консенсуса.
По умолчанию Ed25519; есть режим HMAC. `make chain-verify` проверяет локальную
цепочку, `make chain-export` экспортирует её. Для подлинности проверки нужен
независимо закреплённый открытый ключ; для обнаружения отката/удаления хвоста —
сохранённый внешний якорь или актуальная независимая копия.
Один открытый ключ внутри экспортированной цепочки не доказывает её подлинность.

Действия по кейсу пишутся с блоком в одной SQLite-транзакции. Для действий с
учётными записями используется транзакционный outbox с повторной доставкой;
временно возможны pending-события. HTTP `/triage` пытается записать аудит до
возврата ответа, но сбой журнала не блокирует результат. CLI и оценочные прогоны
в цепочку не пишут. Вход через OIDC происходит у провайдера и не создаёт локальное
событие входа оператора.

В цепочке есть идентификаторы, метаданные и хеши, но нет исходных текстов обращений
и черновиков. Несолёные хеши коротких текстов могут подбираться; экспорт не считается
анонимным. Ключ по умолчанию создаётся рядом с базой. Владелец сервера с ключом может
переписать локальную историю; её проверяют относительно независимых свидетельств.
Настройка ключей, якорей и отдельная демо-проверка подделки:
[docs/audit-chain.md](docs/audit-chain.md).

Есть Docker/Compose и конфигурации Caddy/OIDC. Активация SSO/MFA у провайдера,
публичного TLS, защиты ветки GitHub и независимого пентеста не подтверждена.
Подготовленная конфигурация не означает готовое публичное развёртывание:
[docs/production-access.md](docs/production-access.md),
[docs/security-audit.md](docs/security-audit.md).

## Данные и оставшиеся ограничения

Организаторский README из handout разрешает данные только для решения кейса,
запрещает деанонимизацию и публикацию данных/их частей и требует удаления в течение
14 дней после объявления победителей. Датасеты, производные выборки и карточки
разметки не включаются в PR. `data/`, `outputs/`, локальные базы, `.env`, `*.key`
и `*.pem` исключены через `.gitignore`; `make audit-repo` проверяет доступную
историю Git по своим правилам. В `examples/` — вручную написанные примеры.

Удаление по сроку действует только на старые закрытые кейсы и связанные рабочие
записи после явного `--apply`. Открытые кейсы, подписанная цепочка, базы учётных
записей, резервные копии и экспорты требуют отдельного учёта. Полное удаление
персональных данных этим механизмом не обеспечивается.

Главные пробелы: независимая оценка черновиков и носителями KK/UZ ещё не получена;
