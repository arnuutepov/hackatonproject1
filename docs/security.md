# Защита операторской панели · 0.9.0

31 октября 2026. Основа — main после mock-коннектора, `749a47d`.
Авторизация включена по умолчанию. Общего пароля, публичной регистрации и
автоматического создания первого администратора нет.

## Какие проблемы устранены

| Прежняя граница | Новое поведение |
|---|---|
| Host localhost воспринимался как доступ | Нужна серверная сессия; Host не подтверждает личность |
| Origin мог отсутствовать | Cookie-запись без точного Origin получает 403 |
| /triage открыт, возможен платный вызов | Нужна сессия или отдельный токен только для triage/health |
| Роль player/admin выбиралась в теле чата | Поле role удалено и отвергается; оператор пишет как admin |
| local_operator в назначениях и аудите | Сохраняется ID вошедшего сотрудника |
| Любой мог читать очередь/outbox | Все HTTP-маршруты закрыты по умолчанию, включая будущие и docs |
| Выдача себя за игрока через simulate-ticket | Эмулятор только для вошедших сотрудников; реальный приём отдельно под HMAC |
| Log Out лишь закрывал экран | Серверный токен отзывается, cookie удаляется |

Текстовый контракт `/triage`, классификатор, правила и генерация не изменены.
Игровые санкции и фактическая доставка ответов не появились: исходящий outbox
по-прежнему MOCK. Подписанный вход уже реализован, но реальный игровой сервер
ещё не настроен на его вызов.

## Первый запуск: владелец создаёт учётную запись

Linux/macOS, из папки проверенной ветки:

```bash
make install
.venv/bin/python -m support_copilot.manage_operators create --username arnur --role admin
```

CLI дважды запросит пароль без отображения и передачи в аргументах процесса.
Минимум 15, максимум 256 символов. Владелец выбирает пароль сам; в Git или журнал
он не попадает. Не отправляйте пароль в чат.

Локальный HTTP с настоящей авторизацией:

```bash
COPILOT_INSECURE_LOCAL_HTTP=1 make serve
```

Открыть `http://127.0.0.1:8000/auth/login`. Разрешение HTTP действует только для
настоящего loopback peer и loopback-host. Приложение по-прежнему запускается на
127.0.0.1; Makefile и run.ps1 явно отключают доверие к proxy headers.
Для HTTPS переменная не требуется; cookie имеет Secure по умолчанию.

Windows:

```powershell
./run.ps1 -Install
.venv/Scripts/python.exe -m support_copilot.manage_operators create --username arnur --role admin
$env:COPILOT_INSECURE_LOCAL_HTTP = '1'
./run.ps1
```

Другие сотрудники создаются тем же CLI с `--role agent` / `--role lead` либо
администратором через API. Изменение роли и отключение сотрудника отзывает все
его сессии. Сброс забытого пароля владельцем:

```bash
.venv/bin/python -m support_copilot.manage_operators reset-password --username arnur
```

Первичная выдача доступа — только через владельца машины. Базы в
`outputs/operator/` локальные и игнорируются Git. Не копируйте Linux-venv на Mac.

## Сессии, пароли, браузер

- Пароли: scrypt N=2^17, r=8, p=1, случайная соль 16 байт. Только хеши в БД.
  Параметры соответствуют варианту scrypt из
  [OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html).
- Токен сессии: 32 случайных байта; в SQLite хранится SHA-256 токена. Cookie
  `oguzki_session`: HttpOnly, Secure по умолчанию, SameSite=Strict, Path=/, без Domain.
  Срок — 8 часов, абсолютный. В local HTTP Secure снимается только явной настройкой.
  Сессии не хранятся в localStorage или URL.
- При входе создаётся новый токен, прежняя cookie-сессия отзывается. Есть выход
  с текущего устройства и отзыв всех сессий. Отключённый сотрудник не проходит
  проверку даже с ещё не истёкшей cookie.
- Постоянный лимит входа: до 10 попыток на имя и 30 на сетевой peer в минутном
  окне, в том числе успешных. Два параллельных scrypt-проверяющих на процесс;
  занятые слоты возвращают 429. Для неизвестного имени тоже выполняется KDF.
- На cookie-записях Origin обязателен, Sec-Fetch-Site=cross-site запрещён.
  Это отдельная защита CSRF, не замена авторизации. Рекомендации:
  [OWASP Session Management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html).
- CSP без unsafe-inline, no-store, nosniff, no-referrer; HSTS при HTTPS.
- Публичны только GET/POST `/auth/login` и два ресурса этой формы. Без сессии
  корень показывает форму с HTTP 401; `/docs`, `/openapi.json`, ассеты панели,
  `/health`, API оператора и outbox закрыты. WebSocket по умолчанию отвергается.
- Хранилище авторизации недоступно — 503, а не обход защиты. Ошибки не повторяют
  пароль, текст обращения или токен. База авторизации получает права 0600 на Unix.

## Полномочия

| Возможность | agent | lead | admin |
|---|:---:|:---:|:---:|
| Читать общую очередь, анализировать, править ответ | да | да | да |
| Создавать демо, писать операторское сообщение, mock-ответ/эскалация | да | да | да |
| Брать свободный кейс, снимать своё назначение | да | да | да |
| Менять назначение другого сотрудника | нет | да | да |
| Завершать обычный кейс без обязательной проверки | да | да | да |
| Завершать эскалацию после ручной проверки с комментарием | нет | да | да |
| Управлять учётными записями | нет | нет | да |
| BAN, MUTE, возврат, реальная отправка | нет | нет | нет |

Это общая очередь одной команды. Разделения на организации и изоляции кейсов
между операторами одной команды нет. Неподдерживаемая роль, например player,
получает 403 даже с записью сессии. Роль из HTTP-заголовка или тела не принимается.

Ручное завершение сохраняет отдельную human_review с автором и комментарием,
не переписывает `analysis.needs_human`. Повторный анализ или новое сообщение
игрока отменяет действительность старой проверки. В интерфейсе комментарий
задаётся в поле «Комментарий к решению» до завершения.

API входа: POST `/auth/login` {username,password}; GET `/auth/me`;
POST `/auth/logout`, `/auth/logout-all`. Операторы: GET/POST `/auth/operators`,
PATCH `/auth/operators/{id}` {role,active}. Смена прав отзывает сессии; последнего
активного администратора отключить или понизить нельзя. В identity_audit
фиксируются вход/выход, создание и изменение пользователя, сброс пароля.

## Машинный доступ к триажу

Сервер и разрешённый клиент получают один случайный `COPILOT_TRIAGE_TOKEN`
длиной минимум 32 символа. `Authorization: Bearer …` разрешает **только**
`/triage` и `/health`; попытка доступа к панели/outbox/пользователям — 403.
Токен не даёт роли оператора и не позволяет принимать события от имени игры.
Авторизованный вызов `/triage` может использовать явно включённого модельного
провайдера, поэтому токен следует выдавать только доверенному сервису.

`submission-check` и benchmark создают собственный временный токен, передают
его дочернему uvicorn и вызывают через заголовок. Они не открывают debug-режим
и не используют настоящие ключи команды. CLI-предсказания остаются локальными.

## Подписанный игровой вход

Игрок не передаёт свою роль или операторскую cookie. Доверенный игровой сервер,
проверив игрока в своей системе, формирует событие. Адреса:

- POST `/api/v1/game/tickets` — обращение;
- POST `/api/v1/game/tickets/{ticket_id}/messages` — новое сообщение игрока.

Секреты задаются владельцем через `COPILOT_GAME_HMAC_KEYS`: JSON-словарь
`key_id → случайный секрет` (не менее 32 байт). Значения в репозитории отсутствуют;
`.env.example` — только перечень переменных, файл .env автоматически не читается.
Без настроенного ключа игровой вход закрыт.

Обязательные заголовки:

```text
X-Game-Key-Id: идентификатор настроенного ключа
X-Game-Timestamp: целые Unix seconds
X-Game-Nonce: новый UUID на каждую транспортную попытку
X-Game-Signature: v1=hex(HMAC-SHA256(secret, canonical))
Content-Type: application/json
```

`canonical` — UTF-8 текст без завершающей новой строки:

```text
v1
POST
/api/v1/game/tickets
<точное значение X-Game-Timestamp>
<точное значение X-Game-Nonce>
<sha256 точных байтов тела, lowercase hex>
```

Для сообщений подписывается их собственный путь с ticket_id. Query запрещён.
Сравнение подписи — constant-time через
[Python hmac.compare_digest](https://docs.python.org/3/library/hmac.html#hmac.compare_digest).
Окно времени ±300 секунд; nonce хранится в SQLite и повторно не принимается.
Размер тела ограничен 2 100 000 байт до JSON-разбора.

Событие создания:

```json
{
  "event_id": "033a60ac-2641-4453-94be-03cfc7f96217",
  "player_id": 777123,
  "title": "Застрял в текстурах",
  "channel": "in_game",
  "request": {"kind": "report", "messages": [{"role": "player", "text": "Застрял в текстурах"}]}
}
```

`launcher` соответствует complaint, `in_game` — report. Чужие поля, role=admin
в сообщении и несоответствие канала контракту отвергаются. Ответ содержит лишь
accepted, ticket_id, replayed; доступ к операторскому разбору подпись не даёт.
Анализ входа принудительно локальный, без платной модели. Профиль и транзакции
не запрашиваются и не выдумываются; происхождение показывается как signed_game_server.

Сообщение игрока: {event_id,player_id,text}. Оно принимается только тем же ключом
сервера и для player_id исходного кейса. Роль player назначает сервер. Новый текст
добавляется в входной payload, старые анализ/черновик/ручная проверка сбрасываются.
Администратор через `/operator/.../chat` может добавить только admin-сообщение.

При транспортном повторе нужен новый nonce и подпись, но прежний event_id и
прежнее содержимое: запись не дублируется. Старый nonce даёт 409; изменённое
содержимое с прежним event_id тоже даёт 409. Эти механизмы дополняют друг друга.
Подпись доказывает владение ключом сервера, не истинность слов игрока; проверка
его игровой сессии и доверенная привязка player_id остаются на стороне игры.

## Явный режим разработки

`COPILOT_AUTH_MODE=local` включает безпарольный debug-доступ только с реального
loopback peer и loopback Host. Заголовок X-Forwarded-For не является разрешением.
В этом режиме личность local_operator и роль agent демонстрационные; не использовать
для публичного сервиса. Неверное значение режима даёт 503, а не отключает защиту.
Обычный локальный HTTP с входом — другая настройка: COPILOT_INSECURE_LOCAL_HTTP=1.
Она не отключает сессии. Тесты прежнего ядра явно используют local; проверки
безопасности отдельно включают required или убирают переменную, проверяя default.

## Что проверено и что не настроено

`make check`: 352 теста, включая 34 проверки безопасности; 270/270 регрессий,
133/133 проверок черновиков и 5/5 демо. Есть проверка всех документированных
маршрутов без сессии, будущего маршрута без зависимостей, Host/forwarded spoofing,
ролей, подмены role, отзыва/истечения сессии, Origin, лимита входа, аудита автора,
HMAC/timestamp/nonce/тела/пути, чужого server key, ограничения размера. Один тест
запускает настоящий uvicorn: закрытый triage, HMAC-приём, вход, cookie, CSRF, выход.
Браузером проверена публичная форма входа и загрузка ресурсов без ошибок JavaScript.

Независимый пентест, MFA/SSO игры, развёртывание TLS, резервное копирование и
политики доступа организации не выполнены. Защита приложения не заменяет их.
Настройки GitHub branch protection и CODEOWNERS не менялись: они требуют решения
команды о ревьюерах и правилах слияния. Для публичного размещения владелец должен
настроить TLS/доверенный reverse proxy и SSO/MFA либо внешнюю защиту доступа,
ограничить прямой доступ к backend и определить эксплуатационные процедуры.

## Аудит-цепочка

`GET /audit/verify` и `GET /audit/blocks` доступны любому вошедшему оператору,
`POST /audit/checkpoint` только роли admin. Служебный токен `/triage` к ним доступа не даёт.
Устройство и границы защиты: [audit-chain.md](audit-chain.md).
