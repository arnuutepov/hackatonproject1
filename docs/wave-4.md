# Wave 4 — ошибки, которые обнуляют результат

30 октября 2026 года. Основа — main после PR #4, коммит `5e5e61f`.
Все проверки локальные; внешняя модель не вызывалась.

## Что было найдено и исправлено

Первый прогон новых тестов на Wave 3: 16 из 21 проверки не прошли. Среди проблем
были фактические пропуски эскалации и недостающие признаки неопределённости.
Наличие такого признака и реальная опасная автоматизация — разные виды проверки.

| Сценарий | Прежнее поведение | Исправление |
|---|---|---|
| «Как вернуть учётную запись?», взлом с латинской o, payment с кириллическими буквами, списание с карты | Могли остаться обычным вопросом без человека | Независимая проверка риска до модели, приоритет p0 и обязательная передача |
| Платёж + взлом + апелляция | Сохранялась одна категория без списка остальных тем | Все обнаруженные темы сохраняются; есть mixed_sensitive_topics и пояснение в черновике |
| Заявление и последующее опровержение | Не было отдельной обработки противоречия | Нужен человек; модель не может выбрать одну цитату как единственную версию |
| Разные номера сервера в сообщениях | Извлекался первый номер | server=null, запрос уточнения и обязательная проверка |
| Подмена инструкций | Защита текста работала через контролируемый рендеринг, но не было отдельного решения о проверке | Признаки подмены вызывают обязательную эскалацию и блокируют цитирование |
| Смешанная речь и подозрительная порча KK | Мог ошибочно выбираться один язык | Явный und и запрос языкового предпочтения; спорная таблица замен не применяется |
| Медленный ответ по байту | Сокетный таймаут не ограничивал суммарное ожидание | Общий лимит ожидания, поздний ответ не меняет уже возвращённый шаблон |
| Много одновременно зависших вызовов | Общего ограничения не было | Не более четырёх активных вызовов в процессе; без очереди, при занятости безопасный шаблон |

Проверки вложений и запрета обещаний уже работали в Wave 3. Для них добавлены
дополнительные регрессии; наличие нового теста не означает, что раньше здесь была ошибка.

## Что теперь обеспечивает код

`safety.py` проверяет сообщения независимо от выбранной категории. Платежи, доступ
и апелляции выявляются отдельными лексическими признаками RU/KK/UZ/EN. Для поиска
признаков используется отдельное представление текста: NFKC, удаление невидимых
форматирующих символов, унификация апострофов и небольшая таблица омоглифов внутри
смешанных слов. Исходные сообщения и отображаемые цитаты не заменяются.

`detected_topics` и `safety_flags` добавлены в ответ. Смешанные чувствительные темы,
противоречия, попытки подмены инструкций и проблемы языка не могут быть отменены
планом модели. Риск в reported_player требует проверки, но не заменяет намерение
заявителя при классификации. При противоречиях формулировка явно просит уточнение.

Повреждённые казахские символы не заменяются без доказанного контекста. Буквы,
общие для казахского и узбекского, сами по себе не устанавливают язык. Неоднозначные
и смешанные варианты направляются человеку с lang=und. Это консервативная эвристика,
а не полноценное распознавание языков.

Проверка цитирования состоит из отдельных условий:

1. ID существует в локальном справочнике и содержит раздел, а не только номер.
2. Источник действительно входил в отправленные модели кандидаты.
3. Цитата точно совпадает с подстрокой отправленного фрагмента и исходного пункта.
4. Выбранный фрагмент содержит предметную тему, а не только общий термин вроде «сервер».
5. Специальный раздел требует контекстного признака: например, правила лидеров
   не предлагаются по обычной жалобе без упоминания лидера.
6. При противоречиях, подмене инструкций и других блокирующих признаках цитирование
   отключено. Точная цитата из реального, но неприменимого пункта не проходит проверку.

Это более строгий фильтр кандидатов, не автоматическое установление юридической
или игровой применимости. Номера специальных разделов относятся к текущему
зафиксированному справочнику; при смене правил эту политику нужно пересмотреть.

Запрет обещаний и просмотра изображений обеспечивается контролируемым рендерингом:
произвольная проза модели не попадает в конечный текст. `has_evidence=false`,
`established_facts=[]`. Число вложений 0/1/145/10000 не меняет эти свойства и само
по себе не повышает приоритет. Заявленная передача человеку не выдаётся за реально
выполненную интеграцию с очередью.

## Срок ожидания и отказ провайдера

`COPILOT_DRAFT_TIMEOUT` ограничивает ожидание вызова модели целиком, по умолчанию
четыре секунды, допустимо больше нуля и до десяти секунд. Остаётся и сетевой таймаут.
Вызов выполняется в отдельном daemon-потоке, получает копию контекста и занимает
один из четырёх слотов. Очередь не накапливается. Проверяются коды
draft_provider_timeout, draft_provider_busy и безопасный возврат полного контракта.

Python-поток невозможно принудительно безопасно остановить: после таймаута
внутренний вызов может продолжаться и держать слот до завершения. Поздний результат
отбрасывается. Если все четыре вызова зависнут навсегда, сервис продолжит отвечать
шаблонами; для восстановления модельной мощности может потребоваться перезапуск.
Этот механизм не является процессной песочницей и не гарантирует прекращения
работы внешнего провайдера или списания за уже отправленный запрос.

## Проверки

- **219 тестов прошли**, включая 44 добавленных проверки Wave 4.
- **270/270** синтетических проверок: 30 сценариев × девять режимов модели.
- **133/133** прежних синтетических проверок Wave 3 сохранены.
- Отдельный настоящий локальный HTTP-сервер отправляет ответ по байту: общий
  лимит срабатывает до завершения передачи. Проверены ограничение слотов,
  неизменность ответа после позднего результата и невозможность изменить копией
  контекста исходное требование эскалации.
- HTTP/CLI возвращают одинаковый полный JSON при занятости модели; остальные
  старые проверки неверного JSON, отказов, ошибок HTTP, языков и цитат сохранены.
- Есть контрольные обычные обращения без обязательной эскалации: защита не сведена
  к безусловному needs_human=true во всех сценариях.
- Все 1000 официальных valid inputs обработаны с полным черновиком. Это совместимость,
  не оценка смыслового качества всех ответов.

На прежних 100 dev-примерах, без изменения меток: категория **60%** (Wave 3: 58%),
язык **78%** (было 79%), priority macro-F1 по всем четырём классам **0.4355**.
Точность языка снизилась на один процентный пункт; улучшение распознавания языков
не заявляется. По-прежнему направлены человеку все 100 dev-случаев, в том числе
65 обязательных по меткам; это не доказательство эффективности автономной обработки.
Все замороженные хеши данных совпадают. Независимость старого AI-control не заявляется.

Протокол и исходные синтетические сценарии: `evaluation/wave4-protocol.json` и
`evaluation/wave4-cases.json`. Полный локальный отчёт: `outputs/wave-4/regressions.json`.
Старый набор: `outputs/wave-4/wave3-regression.json`. Реальные данные и локальные
отчёты не включаются в Git.

```powershell

```

Без PowerShell: `python -m support_copilot.evaluate_regressions --output outputs/wave-4/regressions.json`.
Linux/macOS: `make eval-regressions`. Нужны локальные rules.json и taxonomy.json.
Внешняя модель для этих проверок не используется даже при настроенном ключе.

## Границы результата

Критерий выполнен на перечисленных регрессионных сценариях. Категории риска,
языки, смешанные темы и противоречия распознаются ограниченными эвристиками:
произвольные новые перефразы или редкие кодировки могут потребовать новых правил
и тестов. Существующая таксономия остаётся draft. Качество живой модели,
независимая оценка носителями языков, стоимость и производственный p95 не измерены.
