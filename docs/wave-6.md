# Wave 6 — локальное рабочее место оператора

## Результат и база разработки

Новый интерфейс написан с нуля в `support_copilot/static/`; прежний внешний
HTML-прототип не копировался и не используется. FastAPI обслуживает HTML/CSS/JS
и отдельные маршруты `/operator/*`. Node, frontend build, CDN, внешние шрифты
и новые Python-зависимости для запуска не нужны.

Визуальный референс — [официальная статья об обновлении лаунчера GRAND MOBILE](https://support.grnd.gg/ru/articles/13234161-обновление-лаунчера-grand-mobile),
включая скриншоты главного окна и настроек: тёмно-фиолетовая основа, лиловые
выделения, светлый текст и жёлтая основная кнопка. Палитра — адаптация этих
скриншотов, а не заявленные официальные design tokens. Код интерфейса и знак
прототипа написаны отдельно; скриншоты, фоны игры, внешние шрифты и игровые
ресурсы не встроены. Авторство Oguzki и локальный режим обозначены в интерфейсе.

База: `main`, коммит `b3679df` после слияния PR №3–6 с Waves 2–5.
До изменений прошли 250 тестов. В этой итерации не менялись классификатор,
промпты, политика генерации и контрольные метки. Поэтому старые показатели
Wave 5 остаются результатами той версии, а не новой оценкой качества Wave 6.

Анализ GitHub показал:

- В `main` уже есть триаж, retrieval, контролируемые черновики и runtime-защита.
- Пользовательского интерфейса и долговременного журнала решений там не было.
- Внешний провайдер выключен по умолчанию; доступны локальные шаблоны.
- Независимые оценки, качество KK/UZ и стоимость/задержка живой модели остаются
  незакрытыми вопросами Wave 5. Интерфейс этого не исправляет и не скрывает.

## Запуск

Нужны разрешённые локальные `data/handout-2026-10-27/rules.json` и `taxonomy.json`.
Обращения train/valid для интерфейса не требуются и автоматически не загружаются.

Linux/macOS:

```bash
make install
make serve
```

Windows:

```powershell
./run.ps1 -Install
./run.ps1
```

Открыть http://127.0.0.1:8000/ — рабочее место.
http://127.0.0.1:8000/docs — документация API.
Первый install требует интернет; сам интерфейс загружает ресурсы только с сервера.
`.env` автоматически не читается: настройки задаются в окружении процесса.

По умолчанию очередь пуста. Кнопка «Добавить примеры» создаёт шесть специально
написанных вымышленных обращений: RU, KK, UZ, жалоба с двумя сторонами,
неизвестный пункт, платёж и техническая помощь. Повторное нажатие не создаёт дубли
и не сбрасывает существующие решения. Кнопка не вызывает модель; анализ запускается
отдельно. Это синтетические сценарии, не языковая оценка людьми.

## Сценарий оператора

1. Добавить примеры или создать своё обращение: заголовок, канал, сообщение,
   количество вложений, необязательный ответ второй стороны.
2. Выбрать обращение, нажать «Проанализировать».
3. Проверить категорию, приоритет, язык, маршрут и причины. В списке есть поиск,
   фильтры статуса, приоритета, языка и обязательной проверки человеком.
4. Открыть пункт: показываются раздел, составной ID, полный текст и SHA-256 источника.
   Кандидаты поиска отделены от пунктов, фактически процитированных в черновике.
   Цитаты видны сразу, дополнительные кандидаты раскрываются по запросу.
5. Исправить черновик, при желании сравнить его с исходным и добавить комментарий.
6. Сохранить правку либо отметить передачу человеку. Ctrl/Cmd+S сохраняет решение.
7. Перезагрузить страницу: очередь, последний текст, статус и история доступны из БД.
   Несохранённый текст не сохраняется автоматически; перед уходом есть предупреждение.

Надпись «сохранено» означает запись на этом локальном сервере. Сообщение игроку
не доставляется; наказание, возврат, разбан и игровой статус не изменяются.
Эскалация — локальная отметка, а не фактическая доставка другому сотруднику.

`needs_human` модели и таксономии сохраняется независимо от статуса «Сохранено».
Ручная эскалация остаётся после дальнейшего сохранения и повторного анализа.
В интерфейсе нет действия, отменяющего обязательную проверку человеком.

## Хранилище и история

SQLite по умолчанию: `outputs/operator/workspace.sqlite3`, вне Git.
Можно задать `COPILOT_OPERATOR_DB` абсолютным или относительным путём. Относительный
путь считается от рабочего каталога запуска. Конфигурация не задаётся из браузера.

Хранятся:

- исходный inference-запрос, заголовок и происхождение manual/demo;
- последний результат ядра и хэши его справочников;
- редактируемый текст, локальный статус, ревизия, время анализа;
- события создания, анализа, сохранения и передачи человеку;
- исходный черновик каждого анализа, тексты сохранённых версий и комментарии.

Это журнал локального MVP, не защищённый от подделки аудит. Аутентификации и
подтверждённой личности оператора нет. Снимки полных старых результатов анализа
не архивируются: журнал хранит старые тексты и сведения события, последний анализ — целиком.
История не запускает обучение модели автоматически.

Запись выполняется транзакционно с `expected_revision`. Устаревшее окно получает
409 и не перезаписывает новую версию. Анализ выполняется вне транзакции; при конфликте
перед записью его результат не заменяет более новые правки. Если при этом внешний
провайдер уже был вызван, вызов мог иметь стоимость. Автоматических повторов UI нет.
После таймаута браузера нужно обновить очередь: сервер мог закончить запрос.

База содержит сообщения и производные данные; её резервные копии тоже не публикуются.
Обращаться с ней нужно по условиям организаторов, включая срок удаления данных.
Реальные ticket_id/reporter_hash и время события игры не угадываются: ID и время
создания в UI относятся к локальной записи, не к исходному игровому обращению.

## Совместимость и API

`POST /triage`, `make predict` и операторский анализ вызывают один `service.triage`.
Их входные/выходные модели не менялись. Само сохранение текста не вызывает генератор.
`/health` сохраняет прежний идентификатор измеренного ядра Wave 5; версия приложения
и package — 0.6.0. Он не означает, что человеческая оценка закончена.

| Метод и путь | Назначение |
|---|---|
| GET `/` | Новый интерфейс |
| GET `/assets/{name}` | Локальные CSS/JS |
| GET `/operator/config` | Названия категорий/приоритетов, режим, хэши; без ключей |
| GET/POST `/operator/tickets` | Очередь / создание из строгого inference-запроса |
| POST `/operator/demo` | Однократное добавление синтетических примеров |
| GET `/operator/tickets/{uuid}` | Запрос, анализ, текущая правка и события |
| POST `/operator/tickets/{uuid}/analyze` | Анализ с проверкой expected_revision |
| POST `/operator/tickets/{uuid}/decision` | draft, action save/escalate, note, expected_revision |
| GET `/operator/rules/{source_id}` | Полный текст источника по составному ID |

Пример decision:

```json
{"expected_revision": 2, "draft": "Уточните обстоятельства обращения.", "action": "save", "note": "Нужна проверка оператором"}
```

Передать свой analysis или снять needs_human через эти маршруты нельзя:
лишние поля отклоняются. Результат анализа формируется только сервером.

## Границы безопасности и реализации

- Рабочее место и данные `/operator/*` принимают только loopback Host:
  localhost, 127.0.0.1, ::1. Запуск по умолчанию привязан к 127.0.0.1.
- Изменяющие запросы с чужим Origin или cross-site Fetch Metadata отклоняются.
  CORS-разрешение для чужих сайтов не добавлено.
- Это не замена аутентификации: локальные процессы/пользователи компьютера могут
  обращаться к серверу. Не выставлять сервис в интернет или общий reverse proxy
  без отдельной реализации доступа. Исходный `/triage` не становится защищённым операторским API.
- Клиент выводит тексты игроков, модели и правил через textContent; HTML из них
  не исполняется. CSP запрещает inline-скрипты и внешние подключения интерфейса.
- Ошибки валидации, хранения и источников не возвращают тексты запросов, ключи,
  SQL и пути файлов. HTTP-логи сервера сохраняют маршруты с локальными UUID.
- Браузер не получает ключ провайдера. При явном включении responses анализ
  использует настройки существующего серверного провайдера; это может стоить денег.
- История не доказывает факт доставки игроку. Полноценная межтикетная дедупликация,
  синхронизация игры, многопользовательские роли, автоматическое обучение и
  новая логика применимости правил в эту итерацию не входят.
- Эвристика уверенности не отображается как процент правильного ответа.
  Извлечённые сведения и результаты поиска не выдаются за доказанные факты.
- Реальные данные/справочники не встроены в HTML, JS, wheel или Git.

## Проверка

Добавлены 19 проверок: полный цикл API, совпадение с `/triage`, восстановление
из БД/нового клиента, исходный и исправленный текст, обязательная политика,
sticky-эскалация, конфликт двух записей, параллельное сохранение, idempotent demo,
составные ID правил, sanitization ошибок, origin/host, отсутствие ключей и CSP.

Команды:

```bash
make test
make eval-regressions
make eval-drafts
```

JavaScript дополнительно проверяется `node --check support_copilot/static/workspace.js`
при наличии Node; для работы интерфейса Node не нужен.
Статические файлы включены в package-data; wheel проверяется отдельно.

Ручная проверка в браузере выполняется на отдельной синтетической базе в
`outputs/wave-6/`, без реальных обращений и без внешней модели. Снимки интерфейса
и локальные результаты проверок не добавляются в Git.

Фактический результат на Linux/Python 3.13: **269 тестов**, **270/270 регрессий
Wave 4**, **133/133 проверок Wave 3**, `pip check` без конфликтов. Сохранено прежнее
предупреждение Starlette TestClient/httpx. Сборка wheel прошла; наличие и соответствие
HTML/CSS/JS исходным файлам проверено в архиве wheel. Первая попытка сборки без
build isolation не прошла из-за отсутствия setuptools в локальном venv; обычная
PEP 517 сборка с изолированным build-окружением завершилась успешно.

В браузере пройдены: добавление примеров, реальный анализ, правка и сохранение,
восстановление после reload, открытие полного пункта с уточнениями, эскалация,
история, создание своего обращения и фильтр сохранённых. Ошибок JavaScript
в проверенном сценарии не найдено. Проверка — в доступном desktop viewport;
адаптивные CSS-правила добавлены, но запрошенный мобильный viewport средство
просмотра не применило, поэтому реальная мобильная проверка не заявляется.
