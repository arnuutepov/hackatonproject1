# Wave 3 — проверяемый черновик ответа

30 октября 2026 года. Основа — `codex/wave-2`, коммит `f8f9a44`.
По выбору пользователя реализовано и проверено офлайн; подключение ключа отложено.

## Как устроен ответ

1. Прежнее ядро определяет язык, категорию, приоритет, наблюдаемые сведения,
   кандидаты правил и минимально необходимую эскалацию.
2. Для генератора формируется ограниченный контекст: только сообщения player
   (не более шести по 1000 символов), до трёх найденных источников по 2000 символов,
   текущая категория/язык и разрешённые уточнения. При сокращении контекста нужна
   проверка человеком. Ответы admin, исходы разбирательства и вся выгрузка не передаются.
3. Модель возвращает строгий JSON-план: язык, действие, needs_human, опциональную
   цитату заявления игрока, уточнения из разрешённого списка и цитаты правил.
4. Проверяются структура, язык, происхождение каждой цитаты и отсутствие снижения
   эскалации. Проверка существования источника выполняется отдельно от минимальной
   проверки тематического совпадения. Цитата должна быть точной подстрокой отправленного
   фрагмента и оригинала из справочника; ID — именно из отправленных кандидатов.
5. Итоговый текст собирается из локализованных формулировок, а не из произвольной
   прозы модели. Модель выбирает содержание плана, источники и уточнения; свободная
   генерация окончательной формулировки намеренно не включена.

Это ограничивает выразительность, но предотвращает попадание обещаний и ложных
утверждений из модели или пользовательского текста в финальный черновик. Правила
показываются как пункты для проверки, а не как установленный факт нарушения.
Для вопросов по механике без проверенного ответа шаблон предлагает передать вопрос
сотруднику, вместо просьбы повторить уже понятный вопрос.

## Контракт и факты

Сохраняются поля анализа Wave 2. `draft_available=true` означает, что есть пригодный
структурированный черновик, включая безопасный шаблон. В `draft_reply` добавлены:

- `action`: clarify / human_review / rule_review;
- `provenance`: safe_template / validated_model_plan;
- `player_claim`: точная цитата с ID сообщения и статусом reported_by_player либо null;
- `established_facts`: пустой список — факт нарушения здесь не устанавливается.

`cited` содержит только проверенные составные ID вида `30:2.1`. В пользовательский
текст не подставляются исходная жалоба, текст модели или произвольный текст правила.
Отдельная цитата в `player_claim` остаётся явно обозначенным утверждением игрока.
Вложения не просматриваются; `extracted.has_evidence=false`. Если вложения указаны,
черновик объясняет, что их содержимое здесь недоступно и не проверялось.

Фраза о передаче человеку формулируется как необходимое действие. Сервис не
утверждает, что реальный тикет уже передан: интеграции с очередью поддержки нет.
Никаких обещаний наказания, возврата, разбана или сроков выполнения.

## Ошибки и безопасность

Неверный JSON, лишние поля, неизвестные/несуществующие/неотправленные источники,
изменённые цитаты, неизвестные уточнения, неверный язык, попытка снять эскалацию,
отказ, неполный ответ, таймаут и недоступность провайдера приводят к безопасному
шаблону с needs_human=true. Клиент получает полный контракт, а не обломок JSON.
Причины — фиксированные коды; тексты ошибок провайдера и запросы не выводятся в логи.
Модель может усилить эскалацию, но не снять требование ядра. Неопределённый язык
не отправляется модели: возвращается запрос языкового предпочтения.

Для RU, KK и UZ подготовлены отдельные тексты с привязкой к теме и отсутствующим
сведениям. Также есть EN/ES/PT; `und` использует явный двуязычный запрос выбора языка.
Не запрашиваются уже извлечённые сервер и ник. Для платежей и аккаунтов присутствует
напоминание не отправлять пароли, коды входа и данные карты.

## Подключение модели позже

По умолчанию `COPILOT_DRAFT_PROVIDER=template`: сети и ключей не требуется.
Для Responses API задаются переменные окружения процесса:

```powershell
# OPENAI_API_KEY задайте локально, не в чате и не в отслеживаемом файле.
$env:COPILOT_DRAFT_PROVIDER = 'responses'
$env:COPILOT_MODEL = '<имя доступной модели с поддержкой Structured Outputs>'
$env:COPILOT_DRAFT_TIMEOUT = '4'
./run.ps1
```

Ключ и имя модели обязательны для внешнего режима. `.env` автоматически не загружается.
Адаптер использует Responses API со strict JSON Schema и store=false согласно
[официальной документации OpenAI](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses).
Это настройка API-запроса, не обещание отсутствия любых журналов у провайдера.
Без отдельного решения владельца реальные обращения внешней модели не отправлялись.

По умолчанию используется `https://api.openai.com/v1/responses`. Для локального
совместимого сервера можно задать `COPILOT_RESPONSES_URL` на localhost/127.0.0.1/::1.
Другие внешние адреса и редиректы не разрешены. Поддержка локального сервера требует
совместимости именно с Responses API; поддержка всех серверов Ollama не заявляется.
Повторных запросов нет. Размер ответа ограничен 64 КиБ; таймаут задаётся от 0 до 10 с.

## Что ещё не доказано

Живых вызовов модели — **0**. Правильные/ошибочные планы в проверках синтетические;
это не метрика фактического качества LLM. Независимая оценка текстов носителями
KK/UZ и экспертная оценка полезности черновиков не выполнены. Проверка ключа,
доступности выбранной модели и её конкретной совместимости остаётся до подключения.
Существующие control-метки не использовались как независимый человеческий тест.

Поиск и распознавание языка остаются эвристическими; проверка тематического
совпадения не доказывает смысловую применимость правила. Поэтому цитирование
означает «пункт для проверки», а не вывод о нарушении. Смешанная речь, перефразы
и ошибочная классификация могут дать неподходящую тему шаблона. p95 и стоимость
живой модели не измерялись; общий таймаут API не гарантирует p95 до 5 секунд.

Офлайн-критерий «нет выдуманных пунктов и неподтверждённых обещаний на выбранных
сценариях» пройден. Полное закрытие качества живой модели требует следующего прогона
после подключения ключа и человеческой проверки ответов.
