# Локальный mock-коннектор · 0.8.0

31 октября 2026. Основа: `main` после слияния Wave 7, коммит `89a3d30`.
Это исполняемая имитация обмена с игрой, а не доступ к инфраструктуре Grand Mobile.
Профили и транзакции написаны вручную. Telegram и ClickHouse не вызываются.

## Путь обращения

```text
Веб-форма / эмулятор игры
  → POST /api/v1/simulate-ticket
  → Mock Provider: снимок вымышленного профиля по player_id
  → прежний service.triage: safety → knowledge → drafting
  → одна SQLite-транзакция: кейс + envelope + профиль + анализ
  → оператор проверяет и редактирует ответ
  → POST /api/v1/tickets/{id}/actions
  → одна SQLite-транзакция: статус + решение + outbox + история + сообщение ответа
  → проекция outbox в файл-аудит и строка [MOCK OUTBOX] в консоли
```

`safety.py`, `knowledge.py`, `drafting.py`, `service.py`, `/triage` и CLI не изменены.
ID игрока и вымышленная история хранятся отдельно от `TriageRequest`. Профиль
отображается оператору, не подмешивается в инструкции модели, не становится
основанием для наказания или подтверждённым фактом в черновике.

## Демонстрация в браузере

1. Обычная установка: `make install`. Справочники должны лежать локально в
   `data/handout-2026-10-27/`; проверка хешей остаётся прежней.
2. `COPILOT_DRAFT_PROVIDER=template make serve`, открыть `http://127.0.0.1:8000/`.
3. Нажать «Загрузить тестовый кейс». Выбрать сценарий или «Своё обращение + ID игрока».
4. «Загрузить и разобрать» создаёт обращение с готовым анализом. Раскрыть блок
   `MOCK · игрок …`: ник, сервер, баланс, время снимка и до трёх транзакций.
5. Проверить категорию, язык, флаг подмены инструкций, основания и черновик.
6. Выбрать «Чат игры · MOCK» или «Telegram · MOCK». Нажать «Отправить ответ · MOCK»
   либо «Передать человеку». Автоматически откроется вкладка «Доставка · MOCK».
7. Показать ID действия, адресата, канал и отметку «доставки нет»; открыть текст
   события. Через «Обновить журнал / повторить запись файла» восстановить файл,
   если его запись не удалась.

Для обычных вручную созданных обращений без envelope коннектора старая кнопка
передачи человеку сохраняет локальное решение; кнопка mock-отправки скрыта.
Локальный чат по-прежнему допускает демонстрационные сообщения обеих сторон и
не является игровой перепиской. Только кнопки mock-отправки/эскалации создают outbox.

### Сценарии и профили

| scenario_id | Сценарий | player_id |
|---|---|---:|
| payment_ru | RU, непоступивший донат, тестовая pending-транзакция | 777123 |
| account_kk_injection | KK, доступ к аккаунту и попытка изменить инструкции/приоритет | 4582 |
| stuck_uz_injection | UZ, застревание и попытка изменить инструкции/приоритет | 880012 |
| complaint_ru | RU, оскорбление и непросмотренное вложение | 4582 |
| unknown_player | Нет профиля, ссылка на несуществующий пункт 77:7.7 | 999999 |

Для первых двух профилей есть три операции, для 880012 — пустая история. Для
неизвестного ID возвращаются `lookup_status=not_found` и `profile=null`.
Баланс и историю система не придумывает. Валюта `DEMO_COINS` вымышленная.
Снимок фиксирован, не обозначает время настоящего запроса к игровым данным.

## HTTP API

Все новые пути доступны только через loopback-host и защищены той же проверкой
Origin/Sec-Fetch-Site, что `/operator`. Ошибки валидации не повторяют входной текст.
Это локальный MVP без аутентификации; не публиковать как игровой webhook.
Схемы и вызовы доступны в `/docs`.

| Метод и путь | Назначение |
|---|---|
| GET /api/v1/connector | Режим mock, каналы, пять сценариев |
| POST /api/v1/simulate-ticket | Идемпотентное создание и анализ обращения |
| POST /api/v1/tickets/{ticket_id}/actions | Идемпотентная имитация reply/escalate |
| GET /api/v1/outbox | Последние 100 действий + повтор экспорта полного файла-аудита |

Сценарий:

```json
{
  "event_id": "89eff90d-4ad3-47f7-981b-77055159e725",
  "scenario_id": "account_kk_injection",
  "channel": "game_chat"
}
```

Своё обращение:

```json
{
  "event_id": "62f07d04-ed50-4169-985c-46a487c8e197",
  "title": "Не поступил донат",
  "player_id": 777123,
  "channel": "telegram",
  "request": {
    "kind": "report",
    "messages": [{"role": "player", "text": "Оплатил донат, баланс не изменился. Сервер 7.", "attachments": 0}]
  }
}
```

Нужен ровно один источник: `scenario_id` **или** `title`, `player_id`, `request`.
Профиль и параметры сценария нельзя переопределить произвольным контекстом.
ID — положительное целое до 2^53−1; строки и bool отвергаются.
Новый кейс: HTTP 201, повтор: 200. Ответ содержит `mode`, `replayed`, `ticket`.
`ticket` имеет прежние поля плюс `connector` и `outbox`; исходный контракт `/triage`
не меняется. Созданный кейс имеет revision 2: создание, затем анализ.

Исходящее действие (подставить ticket_id и текущую revision из ответа):

```json
{
  "action_id": "68ef6ce8-647f-4e90-a42b-bc80265ac466",
  "expected_revision": 2,
  "action": "reply",
  "draft": "Передадим сведения специалисту поддержки для проверки.",
  "note": "Оператор проверил черновик",
  "channel": "game_chat"
}
```

`action` — только `reply` или `escalate`; бан, мут, возврат денег и произвольные
команды отсутствуют. `reply` задаёт статус `reply_simulated` и добавляет локальное
сообщение администратора; `escalate` задаёт `escalated`. Обе операции сохраняют
анализ и исходный текст. Эскалация остаётся обязательной после новых правок,
назначений и повторного анализа. Ответ не снимает `needs_human` и не завершает кейс.

Ответ действия: `ticket`, `event`, `replayed`, `audit`, `mode=mock`.
Событие содержит `action_id`, `ticket_id`, `revision`, `player_id`, `channel`,
`action`, UTC-время, текст, комментарий, `status=simulated`, `delivered=false`.

## Повторы, конфликты и аудит

- Клиент генерирует UUID до запроса. Для повтора после потери ответа отправляет
  **тот же UUID и тот же исходный JSON**, включая expected_revision.
- Повтор не создаёт тикет/сообщение/outbox и не увеличивает revision. Повтор
  ingestion не вызывает анализ заново, возвращает сохранённый снимок.
- Тот же UUID с другим содержимым или для другого кейса: 409. Новый action_id
  с устаревшей revision: 409. Это защита от повторной доставки события,
  а не распознавание смысловых дубликатов жалоб.
- SQLite-транзакции `BEGIN IMMEDIATE` сериализуют запись. Повтор ingestion,
  пришедший одновременно с первым, возвращает уже созданный кейс.
- Таблицы `connector_inbox` и `connector_outbox` создаются без удаления прежних
  кейсов. Базу задаёт `COPILOT_OPERATOR_DB`; по умолчанию прежний
  `outputs/operator/workspace.sqlite3`.
- Файл по умолчанию — `mock-outbox.audit.jsonl` рядом с БД. Путь можно изменить
  через `COPILOT_CONNECTOR_AUDIT`. Записывается весь outbox по порядку, включая
  события за пределами последних 100 в HTTP-списке.
- Файл является восстанавливаемой проекцией SQLite: временный файл → fsync →
  атомарная замена. Экспортеры сериализованы на БД, старый снимок не перезапишет
  новый. Это не криптографически защищённый или неизменяемый внешний журнал.
- При ошибке файла действие остаётся в БД, `audit.status=pending`. Повтор
  исходного действия или GET outbox восстанавливает файл без новой отправки.
- Консоль содержит `[MOCK OUTBOX]`, ID и канал, без текста обращения/ответа.
  Повтор действия не создаёт повторную строку консоли. Надёжный первичный аудит — БД.

Справочники, БД, файл-аудит и реальные тексты остаются в игнорируемых путях.
Чтение outbox инициирует восстановление файла только локально, без сетевых отправок.

## Граница настоящей интеграции

Для подключения реальной игры потребуется согласованный с командой Grand Mobile
контракт событий/ответов, авторизация источника, разрешённый доступ к профилям,
производственные адреса и подтверждение доставки. Сейчас этого нет.
Поля адаптера и отдельный outbox подготовлены для такой работы, но транспорт,
ретраи внешнего получателя и его acknowledgements здесь только имитируются.
Автоматического изменения баланса, санкций или возвратов нет.
Первичный анализ simulate-ticket принудительно локальный; обычная кнопка
повторного анализа продолжает учитывать прежнюю конфигурацию провайдера.
