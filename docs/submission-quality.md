# Проверка сдачи и roadmap · 0.11.0

## Исходная версия

Работа начата **с пользовательского oguzki.rar**, а не с прежнего main. SHA-256:
`4c54da4b18a5c52533656ec29a8f7a918245f39e32a644b01795029f872233b2`.
Архив импортирован отдельным коммитом ac9f679. Его 458 тестов прошли до изменений.
В Git не помещены сам архив, справочники, обращения, SQLite, ключи и сырые отчёты.

Проверена добавленная Wave 8: подписи Ed25519/HMAC, цепочка хешей, порядок блоков,
откат, параллельные append, зеркало/якоря, API и UI. Это подписанный журнал одного
узла, не распределённый блокчейн. Внешние якоря остаются обязанностью владельца.

### Исправления найденных проблем

1. Административное действие и блок писались в разные базы до commit действия.
   Это позволяло оставить подписанное событие действия, которое затем откатилось.
   Теперь identity_chain_outbox записывается в одной транзакции с действием;
   публикация после commit идемпотентна по origin_event_id. При сбое событие остаётся
   pending, а последующая транзакция повторяет доставку. `/audit/verify` показывает
   identity_outbox_pending. Нельзя обещать мгновенное совпадение двух БД: доставка eventual.
   Проверены rollback без ложного события и восстановление после неверного ключа без дубля.
2. Семь B608 Bandit относились к константному списку SQL-столбцов, а не вводу пользователя.
   Запросы сделаны статическими; подавления находок не добавлялись.
3. SQLite для обращений, идентификаций и цепочки использует WAL и busy_timeout.
4. Приватные signing keys исключены из Git. Добавлено маскирование известных форм
   секретов/контактов перед внешним API; контрольные поля и enum не изменяются.

## Фактические метрики

Все интервалы ниже — percentile bootstrap по 2000 повторным выборкам кейсов,
seed=20261031. Dev уже использовался для настройки; эти интервалы не доказывают
качество в генеральной совокупности. Control имеет предварительные метки ассистента.

| Метрика | Dev: 100 человеческих меток | Control: 100 silver-меток |
|---|---:|---:|
| Language accuracy до правок | 78% | 67% |
| Language accuracy после | **94%, 95% CI [89%; 98%]** | **77%, CI [68%; 85%]** |
| Category accuracy | 60%, CI [50%; 69%] | 57%, CI [48%; 66%] |
| Precision эскалации | 65% (65 TP, 35 FP) | 69% (69 TP, 31 FP) |
| Recall эскалации | 100% (0 FN) | 100% (0 FN) |
| needs_human | 100% | 100% |

100% эскалаций не представляется успехом автоматизации. Это консервативная политика,
включая обязательного человека для жалоб и отсутствие подтверждённых инструкций
для части вопросов. Её не ослабляли ради красивого precision. Следующий шаг —
независимо проверить ошибки классификации и достаточность базы знаний.
Уверенность low/medium/high отображается отдельно, но остаётся эвристической;
вероятность правильности и калибровка не заявлены. Система пока не выдаёт high
только ради автоматического ответа.

### Retrieval

Добавлены BM25 и символьные триграммы с reciprocal rank fusion; оригинальный
лексический поиск сохранён как mode=legacy для сравнения. Текст источников не
генерируется и не заменяется. Слабые символьные совпадения без лексического подтверждения отбрасываются,
чтобы поиск не заполнял нерелевантными правилами запрос «Застрял в текстурах».
Небольшие явные RU/KK/UZ расширения запросов
используются только в поиске, а не как доказательство или цитата.

На **7 существующих синтетических** запросах оба режима: recall@5=1.0, MRR=1.0,
hit@5=1.0, precision@5=0.2. Это не измеренный прирост: исходный набор уже насыщен.
Нужна отдельная независимая разметка релевантности на реальных запросах.

### Производительность и model-on

- Настоящий localhost HTTP, **300 запросов, 8 клиентов**, шаблоны + SQLite WAL +
  подписи/журнал: p50=35,98 мс, p95=148,57 мс, max=477,06 мс, ошибок 0.
  Это не внешняя сеть и не production capacity.
- Шесть новых synthetic red-team вызовов Capybara/Qwen с timeout 10 с: проверенных
  планов 0/6, безопасный fallback 6/6, p95=10,05 с — SLA не выполнен.
- Повтор отдельного эксперимента со штатным deadline 4 с: проверенных планов 0/6,
  fallback 6/6, p95=4,05 с. Safety сохранён, но качество model-on не подтверждено.
- Usage после timeout не получен вовремя. **Стоимость не равна нулю: она неизвестна**.
  Среднее списание, биллинг и жёсткий предел $0.002 не подтверждены. Не выдавайте
  модель за работающую без fallback; для сдачи воспроизводимый default — template.

### Feedback loop

Сохранение изменённого черновика через decision/mock-action создаёт operator_feedback
в транзакции с правкой. Старый и новый тексты остаются для независимой проверки.
Кнопка **«Разметка правок»** открывает очередь для lead/admin. Автор не может
подтвердить собственную правку; опубликованные метки нельзя незаметно переписать.
Проверка меток не изменяет analysis, needs_human, safety и историю решения.
`make feedback-export` экспортирует только подтверждённые метки/псевдоним и revision,
без сырого текста, ника и actor. Это кандидаты для следующей версии разметки, а не
доказательство хорошего ответа и не разрешение автоматически дообучать модель.

### Privacy / retention

Перед API маскируются распознаваемые ключи, email, телефоны/длинные платёжные ID,
IPv4 и типовые игровые ники. Регулярки не находят все имена и смысловые идентификаторы;
передача посреднику не становится полностью анонимной. Несовпавшая после маскирования
цитата/claim будет отклонена исходным валидатором и заменена шаблоном.

`make retention-preview` ничего не удаляет. Локальный администратор может выполнить
`python -m support_copilot.privacy --days 30 --apply`: удаляются только закрытые
resolved-кейсы старше порога и их operational child records, затем checkpoint/VACUUM.
Открытые кейсы и подписанная цепочка не удаляются. В chain остаются метаданные,
включая ранее записанные player_id, ticket_id/хеши. Бэкапы и экспортированные файлы
не стираются. Это не полное выполнение юридического права на удаление.

## Повторить проверки

```bash
make check
make quality-report
make gold-packet
make load-check
# Optional QA, отдельное окружение:
python3 -m venv outputs/qa-venv
outputs/qa-venv/bin/python -m pip install -r requirements-dev.lock -r requirements-qa.lock
outputs/qa-venv/bin/python -m pip install --no-deps -e .
outputs/qa-venv/bin/python -m pytest -q tests/test_schema_fuzz.py
# Только с явным согласием на расходы и серверным файлом ключа:
python -m support_copilot.model_on_check --allow-paid-synthetic --output outputs/model-on
```

CI выполняет data-independent набор на трёх ОС, проверку `/triage` на synthetic
knowledge без справочников организаторов, Bandit, pip-audit и Gitleaks с checksum
официального релиза. Финальный security-gate требует успех всех трёх jobs.
Зелёные статусы Windows/macOS не заявляются до настоящего запуска; Linux не эмулирует их.
Полный локальный `make check` требует приватных справочников/разметки.

Приоритеты жюри: черновики 30%, классификация 25%, отсутствие выдуманных правил 20%,
KK/UZ 15%, cost/latency 10%. У проекта пока нет доказанного независимого качества
черновиков: именно два разметчика на подготовленном пакете дадут больше пользы,
чем ещё одна декоративная панель или заявление «всё 100%».
