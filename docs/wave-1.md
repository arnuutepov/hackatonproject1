## Размещение и аудит

Исходные train/valid/rules/taxonomy/README находятся в `data/handout-2026-10-27/`.
Данные, производные выборки, ID и карточки разметки не публикуются в Git.
По условиям организаторов данные удаляются в течение 14 дней после объявления
победителей, если нет отдельного соглашения. Дата объявления пока не известна.
Все команды ниже работают локально, без внешних API.

```bash
make audit-data IN=data/handout-2026-10-27/tickets_train.jsonl.gz OUT=outputs/train-audit.json
make audit-data IN=data/handout-2026-10-27/tickets_valid.jsonl OUT=outputs/valid-audit.json
.venv/bin/python -m support_copilot.dataset compare \
  --left data/handout-2026-10-27/tickets_train.jsonl.gz --right data/handout-2026-10-27/tickets_valid.jsonl \
  --output outputs/train-valid-overlap.json
```

Аудит показывает пригодные/ошибочные записи, повторы ID, отсутствие reporter_hash,
точные повторы диалогов, распределение kind и языковых подсказок, наличие меток.
Ошибки содержат номер строки и описание без текста обращения. Повреждённые
JSON/UTF-8/GZIP завершают команду с ошибкой. Исходный файл не изменяется.

Если category/priority отсутствуют, accuracy/macro-F1 по ним вычислять нельзя.
verdict/punishment/violation не заменяют эти метки. Подсказки lang/server_lang
не являются независимо подтверждёнными языками. Аудит не оценивает модель.

Compare показывает количество пересечений ticket_id, reporter_hash и точных
нормализованных диалогов, без самих ID. Нулевые пересечения не исключают
перефразированные дубли и временную утечку. При пересечениях нужна отдельная
политика исключения связанных групп из настроечных/обучающих данных.
Команда ничего автоматически не удаляет; официальная valid не перераспределяется.

## Подготовка dev/control из train

```bash
.venv/bin/python -m support_copilot.dataset prepare \
  --input data/handout-2026-10-27/tickets_train.jsonl.gz --output-dir outputs/wave1-run-01 \
  --sample-size 100 --seed 42 --control-ratio 0.2
```

Сокращение с параметрами по умолчанию:
`make prepare-data IN=data/handout-2026-10-27/tickets_train.jsonl.gz OUT=outputs/wave1-run-01`.
Существующий выходной каталог не перезаписывается. Ошибочные записи, дубли ID
и отсутствие двух независимых групп блокируют подготовку.

Записи связываются по reporter_hash **или** точному нормализованному диалогу,
включая транзитивные связи. Группы целиком попадают в один раздел.
Без reporter_hash непересечение игроков не доказано. Доля control приблизительная:
смотрите actual_control_ratio и largest_group. Общая фраза «помогите» может связать
много игроков; политику grouping нужно проверить на настоящих данных.

Разбиение и выбор карточек воспроизводимы при одном составе, seed и настройках,
даже при перестановке входных строк. Два прохода; в памяти индекс O(N), не все тексты.
SHA-256 источника проверяется до и после подготовки. При изменении файла результат
не публикуется. До завершения записи выход остаётся во временном каталоге.

| Файл | Содержание |
|---|---|
| dev.inputs.jsonl / control.inputs.jsonl | Только HTTP inference-контракт, подходят для make predict |
| *.metadata.jsonl | ticket_id, reporter_hash, подсказки языка, оригинальные сообщения; связь по номеру строки |
| *.annotations.jsonl | Слепые карточки для ручной разметки без ответа и вердикта администратора |
| split_manifest.json | Раздел каждой записи и включение в разметку |
| summary.json | SHA-256, размеры, аудит и фактическая доля control |

Отбор карточек идёт по кругу между `(lang_hint, kind)` — до 100 на раздел.
Это помогает включить языки меньшинств при их наличии, но **не отражает частоты
рабочего потока**. Метрики такой выборки нельзя выдавать за качество всей популяции.
Категории и редкие приоритеты не балансируются: исходные метки могут отсутствовать.

## Адаптер без утечки

Белый список входа: kind, role, text, attachments. Только player/reported_player
**до первого admin**; ответы admin и последующие реплики удаляются. Порядок берётся
из файла, хронология ts не проверяется. Неизвестная роль до admin — ошибка.
Оригинальный текст сохраняется отдельно, raw-объект не изменяется.
verdict/punishment/violation/category/priority не копируются в запрос или слепые карточки.
Количество вложений не доказывает нарушение и не означает просмотр изображения.

reported_nick/rule_refs_raw/region вне текущего HTTP-контракта и не добавляются
в текст автоматически. Их использование требует согласованного расширения.
Исходные файлы остаются локально для следующих этапов.

## Нормализация

По умолчанию только Unicode NFC. Добавьте `--repair-kazakh` к audit/compare/prepare
одинаково во всех сравниваемых запусках для явного включения замен при lang=kk
или server_lang=kk. Исходник всегда сохраняется рядом с нормализованным текстом.

Из ТЗ: `ќ→қ`, `ґ→ғ`, `ѕ→ң`, `є→ә`, `ј→ө`, `ў→ұ`, `ї→ү` и прописные варианты.
Версия challenge-brief-v1-provisional: сверить с README реальной выгрузки.
Сервер kk не гарантирует язык текста; даже контекстная замена может повредить ник.
Неоднозначная латиница и русские буквы автоматически не транслитерируются.

## Ручная разметка

1. Зафиксировать seed/manifest до настройки модели. Официальную valid не использовать для разработки.
2. Скопировать шаблон *.annotations.jsonl в новый локальный файл; оригинал не редактировать.
3. Разметить category/priority только по настоящей taxonomy.json.
4. Определить lang по тексту, не по server_lang; для неопределимого — und.
5. Указать needs_human: платежи, апелляции банов, подозрения на взлом всегда true;
   спорные факты и наказания требуют администратора. Это инструкция, не готовый классификатор.
6. Указать внутренний псевдоним annotator и notes с основанием/неоднозначностью.
7. По возможности дать второму разметчику независимо проверить KK/UZ и редкие приоритеты.
   Разногласия разрешить по таксономии до оценки, историю сохранить локально.
8. Настраивать промпты/правила/пороги только по dev. Control открыть для зафиксированной
   версии. После настройки на нём набор перестаёт быть независимым.

```bash
.venv/bin/python -m support_copilot.dataset validate-annotations \
  --input outputs/dev-labeled.jsonl \
  --expected outputs/wave1-run-01/dev.annotations.jsonl \
  --taxonomy data/handout-2026-10-27/taxonomy.json
```

Проверяется полнота, уникальность ID, неизменность контекста/раздела, категория,
её соответствие исходному kind при наличии kind в таксономии, приоритет, язык,
bool needs_human и разметчик. Категории из needs_human_always требуют true.
Это проверка формата и явных правил таксономии, не независимая оценка качества решений.
Пока registry categories/priorities поддерживает словарь ID→описание, список строк-ID
или объектов с code/id. В полученном файле используются объекты с code — адаптер
проверен на них. Противоречащие code/id отклоняются; незнакомые форматы не угадываются.

## Важное для Wave 2

Номер points[].ref не уникален между разделами правил. Внутренний ключ RAG должен
включать ID раздела и ref; отображаемая цитата — название раздела и пункт.
Нельзя индексировать все правила словарём только по ref: это перезапишет другие
пункты. Разделы без points требуют отдельной обработки, а не выдуманных номеров.
Метка исходного языка lat не заменяет конкретный язык; в ручной разметке выбрать
реальный язык по тексту или und. Контекстные замены не включаются автоматически.
