# Проверки безопасности · 31.10.2026

Это внутренние автоматические проверки изменений 0.10.0, выполненные тем же
исполнителем, который менял код. Независимый пентест не проведён: внешний
специалист не назначен, договорённости и разрешённый публичный стенд не предоставлены.

## Выполненные проверки и исправления

Полный `make check`: 389 тестов, 270/270 регрессий, 133/133 проверок черновиков,
5/5 демо, 20/20 соответствий HTTP/CLI; p95 17,04 мс на 60 последовательных
локальных HTTP-запросах с шаблонами. Аудит истории Git прошёл.
Compose config проверен с вымышленными настройками без запуска публичного сервера.

- 47 отдельных проверок доступа, OIDC и конфигурации: подпись/issuer/audience/azp,
  MFA, время входа, группы, роли, отсутствие обхода паролем и подставными заголовками.
  Для OIDC использованы синтетические подписанные токены; реальный IdP не подключался.
- Bandit 1.9.4: после исправлений нет находок одновременно средней/высокой
  серьёзности и уверенности (`bandit -r support_copilot -ll -ii`). Находки низкого
  уровня остаются; это не заявление об отсутствии всех дефектов.
- pip-audit 2.10.1: в requirements-dev.lock не обнаружено известных уязвимостей
  на момент запуска. Это не анализ всех системных пакетов контейнеров.
- OWASP ZAP baseline на настоящем локальном uvicorn, без входа в аккаунт:
  FAIL=0, PASS=66, два информационных предупреждения: Non-Storable Content и
  Modern Web Application. Spider получает 401 на защищённом корне — ожидаемое
  ограничение охвата. Четыре первоначальных замечания к isolation/permissions
  headers исправлены. Выход ZAP=2 означает наличие предупреждений, не полный успех.
- Caddy 2.10.2: конфигурация прошла validate; oauth2-proxy 7.15.0 проверен по версии.
  Образы закреплены по digest. Это не проверка live TLS/OIDC всей цепочки.

Исправлены небезопасный XML-разбор workbook (defusedxml с отказом при entities),
HTTP-транспорт локальных проверок (только literal loopback, без proxy из окружения
и переходов по redirect), добавлены COOP/COEP/CORP/Permissions-Policy.
Сырые отчёты находятся локально в игнорируемом outputs/security-audit; секреты,
справочники и пользовательские данные в Git не добавляются.

ZAP baseline выполняет пассивный анализ; он не атакует приложение и не проверяет
авторизованные сценарии. Нулевой FAIL не доказывает защищённость сервиса.
[Описание baseline от ZAP](https://www.zaproxy.org/docs/docker/baseline-scan/).

## Задание независимому специалисту

Владелец назначает специалиста, который не разрабатывал проверяемые изменения,
предоставляет отдельный staging-домен, письменные границы проверки и тестовые
аккаунты agent/lead/admin. Только вымышленные обращения; отдельно согласовать
нагрузку и временное окно. Боевые игровые серверы, платёжные системы и IdP
организации вне разрешённой области, если владелец явно не включил их.

Проверить: обход SSO/MFA; redirect/callback/PKCE/nonce; подмену JWT, groups и
proxy-заголовков; session fixation/CSRF/XSS; межролевой и межобъектный доступ;
отзыв/истечение сессий; HMAC replay/подмену тела; лимиты и конкурентные записи;
аудит действий и утечки данных; ingress/network/TLS и прямой доступ к backend.

Результат: для каждой находки серьёзность, шаги, минимальный PoC на тестовых данных,
затронутая версия, исправление и независимый retest. До отчёта и retest нельзя
отмечать пункт «независимый пентест» выполненным. Обращения к подрядчикам от имени
команды этим изменением не отправлялись.
