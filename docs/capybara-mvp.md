# Capybara MVP: помощник оператора

## Что подключено

Серверный OpenAI-compatible POST к фиксированному HTTPS endpoint
`https://api.capybara-api.xyz/v1/chat/completions`. Авторизация — Bearer, ключ
читается из CAPYBARA_API_KEY_FILE либо CAPYBARA_API_KEY. Ключ не передаётся браузеру,
не включается в запросы к GitHub и не выводится в ошибках.

COPILOT_DRAFT_PROVIDER=capybara явно включает внешнюю обработку. По умолчанию
остаётся template. Допустимые модели: gemini-3.8-flash, qwen-3.8-flash,
deepseek-v4-flash. Автоматического переключения моделей и платных повторов нет.
Название возвращаемой модели — заявление посредника, не независимая проверка
внутреннего поставщика. Документация: https://docs.capybara-api.xyz/.

## Интерфейс и границы

В карточке обращения есть отдельный «ИИ-помощник оператора». POST
`/operator/tickets/{id}/assistant` требует авторизацию оператора, проверяет revision,
не меняет обращение, статус, переписку игрока и outbox. Чат является советом
сотруднику, а не автоматически отправляемым ответом игроку.

На каждый вопрос выполняется детерминированный анализ текущего обращения без
дополнительного вызова модели. В API уходит ограниченный контекст: до четырёх
сообщений игрока по 800 символов, до двух релевантных правил по 1000 символов,
результаты safety и вопрос оператора. Контекст может быть усечён; это не анализ
неограниченного полного архива. Вложения и реальные логи не отправляются.
Последние четыре реплики диалога передаются как недоверенные данные; они живут
только в текущем окне и очищаются при смене обращения/перезагрузке. Это не
постоянная серверная история чата.

Ответ разбирается по JSON-схеме; каждая указанная цитата проверяется на точное
совпадение с переданным правилом. Обязательное напоминание о человеке добавляет
сервер. Свободный совет модели остаётся потенциально ошибочным: не все утверждения
в нём автоматически доказаны. Он не заменяет проверенный черновик, существующие
проверки цитат/эскалации и решение сотрудника. В интерфейсе используется textContent.

Ограничения: максимум 24 KB сериализованного запроса, 700 output tokens для чата,
900 для плана черновика, 64 KB ответа, 10 секунд транспорта и два параллельных
чат-запроса. Переходы по redirect и proxy из окружения отключены. Анализ черновика
сохраняет общий прежний deadline (по умолчанию 4 секунды) и откат к шаблону.
Если модель не успевает, чат сообщает о недоступности; успешный ответ не имитируется.

## Локальный запуск

Владелец сохраняет ключ вне Git в файл с правами 0600. Не вставляйте ключ в
командную строку, исходники или браузер. Пример с путём к уже созданному файлу:

```bash
export CAPYBARA_API_KEY_FILE=/абсолютный/закрытый/путь/api-key
export COPILOT_DRAFT_PROVIDER=capybara
export COPILOT_CAPYBARA_MODEL=qwen-3.8-flash
# С существующими персональными аккаунтами; HTTP разрешать только на loopback:
export COPILOT_INSECURE_LOCAL_HTTP=1
make serve
```

Используйте отдельную базу и только вымышленные кейсы для публичной демонстрации.
Организационный compose по умолчанию остаётся template; передачу реальных обращений
посреднику владелец должен включать осознанно после проверки условий обработки данных.

## Живая проверка 31.10.2026

Ключ принят GET /v1/models. Gemini 3.8 Flash и GPT вернули 503 с сообщением
о недоступном фиксированном поставщике. Qwen 3.8 Flash и DeepSeek Flash ответили
на короткие тесты. Демонстрация интерфейса выполнена на qwen-3.8-flash:
на платёжном обращении модель предложила уточняющие вопросы, не обещала возврат
и сохранила требование человека; usage — 1200 токенов.

Цены динамические. В списке моделей Gemini был указан как $0.18 / 1M и multiplier
1.8; формулу окончательного списания независимо не подтвердили. Стоимость в UI
не выдумывается: выводятся usage и указание проверить кабинет. Жёсткая гарантия
$0.002 на обращение в этом MVP не реализована; настройте дневной лимит в боте
провайдера и проверяйте фактические списания. Скриншот/сырые результаты находятся
локально в игнорируемом outputs/capybara-demo. Ключ, опубликованный в чате,
после демонстрации следует перевыпустить.

Дополнительный живой тест: на узбекском получен ответ (1141 токен, 4,96 секунды).
Казахский запрос через HTTP завершился 503; успешная работа KK через полный
интерфейс не подтверждена. Полный offline make check: 398 тестов, 270/270 регрессий,
133/133 проверок черновиков и 5/5 демо. Bandit: нет medium/high находок.
Тест фиксированного минутного лимита входа стабилизирован фиксированным временем,
чтобы серия запросов не пересекала границу минутного окна; сама политика не менялась.
