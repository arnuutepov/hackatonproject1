# Wave 5 — качество, стоимость и задержка

Состояние на 30 октября 2026 года, Asia/Oral. Основа — main после PR #5,
коммит `7beb459`. Пользователь выбрал подключить ключ и передать пакет
рецензентам позже. Массовая обработка train и вызовы дорогой модели не выполнялись.

## Что измерено

Использован канонический control из 100 записей. Его метки подготовлены Codex,
предварительны и требуют человеческой проверки; ассистент ранее видел эти входы.
Это silver-control, не независимый человеческий ground truth и не слепой тест.
Протокол `evaluation/wave5-protocol.json` зафиксирован до оценки. После получения
метрик правила классификации и языков не подгонялись под ошибки control.
Проверены исходные SHA-256 rules/taxonomy/dev/control до и после прогона.

В control отсутствуют p0 и категории account/payment, поэтому качество критических
классов подтверждается только отдельными синтетическими регрессиями. Состав языковых
меток: RU 41, UZ 20, EN 10, und 28, KK 1. С меткой UZ совпали 6/20 ответов;
с единственной меткой KK совпадения нет. Одного примера недостаточно для вывода
о качестве казахского. Сами языковые метки control также предварительны.

`outputs/wave-5/control-metrics.json`. Нулевая ошибка целостности не доказывает
релевантность поиска. Отсутствие цитат не доказывает качество цитирования.
100% передачи человеку означает отсутствие полезной автономной пропускной
способности на этой выборке, даже при нулевых пропусках обязательной проверки.

## Как получена задержка

Запускался отдельный uvicorn на localhost. После health выполнены пять исключённых
прогревочных запросов, затем три последовательных прохода по всем 100 случаям:
всего 300 измеренных запросов. Время — от отправки готового тела HTTP до разбора
JSON-ответа клиентом; включает транспорт localhost и серверную сериализацию.
p95 — ближайший ранг ceil(0.95 × N), а не интерполяция. Ошибки не исключаются:
неуспешный запрос останавливает прогон. Внешний провайдер отключён принудительно,
даже если в окружении есть ключ. Число проходов ограничено 1–10.

Замер выполнялся на Windows с Python 3.12.14. Полные сведения платформы, все
300 длительностей, SHA-256 кода и health источников находятся в
`outputs/wave-5/http-latency.json`. Это не нагрузочный тест, не WAN и не p95
живой модели. Повторный замер на этой машине может дать немного другие значения.
Локальный предел 5 с соблюдён; производственный предел пока не подтверждён.

## Оптимизации и их реальный эффект

До оценки control введены следующие ограничения:

- До четырёх сообщений по 800 символов вместо шести по 1000.
- До двух фрагментов правил по 1000 символов вместо трёх по 2000.
- Лимит выходных токенов плана 900 вместо 1400.
- Обычно два уточняющих вопроса вместо трёх.
- Точные шаблоны для запроса помощи при застревании и вопроса о доступности
  изображений. Они предлагают следующий шаг поддержки, не выдумывают игровые
  команды. При флагах риска или дополнительном тексте shortcut не применяется.

Верхняя граница содержимого сообщений/правил сокращена с 12000 до 5200 символов,
без учёта системного промпта, схемы и метаданных. Это не оценка числа токенов.
На данных control средний сериализованный контекст остался 363.56 символа:
короткие/неопределённые обращения и так не достигали прежних лимитов. Средняя
длина черновика изменилась с 213.54 до 202.74 символа, примерно на 5.1%; p95 длины
ответа — 420 символов. Полезность сокращённого текста ещё не оценена людьми.

Совпадений точных шаблонов на control **0/100**. Экономия модельных вызовов или
живых токенов на этой выборке не заявляется: провайдер и до этого был выключен.
Пути shortcut отдельно проверены на синтетических RU/KK/UZ-примерах. Значение
`verified_template` означает программно проверенные ограничения, а не одобрение
носителем языка. При сокращении контекста сохраняется обязательная эскалация.

## Учёт стоимости после подключения ключа

В контракт добавлено `generation`: число попыток генерации, доступные счётчики
usage, api_cost_usd и cost_status. При отсутствии вызовов API-расход равен нулю.
При попытке без usage или проверенных цен стоимость остаётся null, не нулём.
Ошибки и отказы с известным usage также могут иметь стоимость; таймаут не означает,
что провайдер прекратил обработку или не выставит счёт.

Адаптер читает input/output/cache usage по
[официальной схеме Responses API](https://developers.openai.com/api/reference/python/resources/responses/methods/create).
Для оценки нужен локальный файл из `evaluation/pricing.example.json` с фактической
моделью ответа, ценами за миллион токенов, URL источника и датой проверки.
Тарифы не придуманы и не зафиксированы для неизвестной модели. Путь задаётся через
COPILOT_PRICING_FILE. Несовпадение модели, отсутствующие значения или неизвестная
семантика cache-write сохраняют стоимость неопределённой.

Стоимость вычисляется по usage, а не делением символов на четыре. Расчёт с тарифами
помечается usage_pricing_estimate: это оценка API, не платёжный документ и не полная
стоимость инфраструктуры/работы человека. Цель $0.002 для живой модели не проверена.
Локальные шаблоны не выдаются за локальную LLM. Число запросов к провайдеру —
не более одного на обращение, без повторов, с прежним общим сроком ожидания.

## Пакет рецензентам

По выбору пользователя подготовлен пакет для последующей передачи людям:

- 100 анонимно перемешанных карточек control без исходных меток, названия версии,
  прогноза категории/приоритета и provenance генерации.
- 98 кандидатов поиска из первых трёх результатов каждого обращения для отдельной
  оценки релевантности. Это не случайная оценка всех 153 результатов поиска.
- Пять явно отделённых синтетических KK-ситуаций. Их оценки не смешиваются с real-control.
- XLSX с выпадающими списками, инструкции, CSV и HTML для чтения длинных текстов.
- Отдельный файл координатора с сопоставлением ID; он не входит в архив рецензенту.

Рецензенты выставят корректность, полезность и язык по шкале 0–3, отметят обещания
и заявления о просмотре изображений, укажут свой язык и уровень владения. NA —
«не могу оценить», а 0 — плохая оценка. Ни одной оценки за людей не внесено.
При импорте нулевой балл сохраняется, пустой не превращается в ноль. Проверяются
ID, дубли, неизменность контекста и ответа, полнота начатых строк и допустимые значения.
Поддерживаются XLSX и CSV с запятой/точкой с запятой/табуляцией, кавычками и переносами.

Скрыты метаданные условия, но сам стиль ответа может быть узнаваем. Независимость
будущих рецензентов ещё не подтверждена. Носители KK/UZ пока не привлечены.
Их оценки не заменят отдельную gold-разметку категории и приоритета.

## Воспроизведение

Нужны локальные файлы по путям `evaluation/frozen-inputs.json`. Они не включены
в Git. Достаточно 100 control, 100 dev для проверки хешей и справочников;
train на 120 тысяч записей для этих команд не нужен.

```powershell
./run.ps1 -Mode Test
./run.ps1 -Mode Measure
./run.ps1 -Mode Benchmark
./run.ps1 -Mode RegressionEvaluate
./run.ps1 -Mode DraftEvaluate

python -m support_copilot.review prepare --output outputs/wave-5-review --predictions outputs/wave-5/control-predictions.jsonl
python -m support_copilot.review import --packet outputs/wave-5-review --xlsx returned-review.xlsx --output outputs/wave-5/human-ratings.json
```

Подготовка создаёт CSV/JSON для рецензента и отдельную карту координатора; уже
выданный пакет автоматически не перезаписывается. XLSX этой итерации дополнительно
сформирован Artifact Tool, визуально проверен по трём листам и повторно прочитан:
все 105 карточек и 98 пунктов сохранились, оценок 0, статус pending. Формулы,
макросы и внешние ссылки при импорте не исполняются.

Linux/macOS: `make measure` и `make benchmark`. Все оценочные команды этой итерации
работают офлайн, даже при настроенном ключе. Сырые control/predictions, карточки,
карта соответствия и человеческие ответы в GitHub не загружаются.

Проверено: **250 тестов**, **270/270 Wave 4** и **133/133 Wave 3**. Конфликтов
зависимостей нет; сохранено прежнее предупреждение Starlette TestClient/httpx.

## Оставшиеся слабости

Для полного закрытия Wave 5 ещё нужны независимые метки, человеческая оценка
черновиков и ссылок, достаточный KK/UZ-контроль, затем маленький согласованный
прогон выбранной модели с актуальными тарифами. Текущие 57% и 100% передачи человеку
не подтверждают готовность автономной поддержки. Большой платный прогон не запускался.
